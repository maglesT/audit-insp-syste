# Decisions

Small decisions taken by the build session, recorded so the owner can overrule any of them.
Owner decisions from the 29 October 2026 brief are summarised in `docs/00-brief.md`.

| # | Date | Decision | Why |
|---|---|---|---|
| D1 | 2026-10-29 | Official PDFs are stored in the private repo under `sources/official/` (about 17 MB) and fingerprinted by sha256 in `sources/inventory.csv`; CI fails if one changes. | Layer 1 needs the exact source bytes. A changed text must trigger re-verification. |
| D2 | 2026-10-29 | FDA regulations come from the eCFR XML API (dated snapshot), not a PDF. | The XML carries section and paragraph structure, so clause references can be checked deterministically. |
| D3 | 2026-10-29 | The PIC/S version is PE 009-18 (24 Sept 2026), the current one. EU and PIC/S are mapped separately and never assumed identical. | PE 009-18 is newer than several EU chapters, so their wording can differ. |
| D4 | 2026-10-29 | Library tooling is Python 3, standard library only, plus poppler-utils. | Simple, no dependency churn. The app stack is decided in deliverable (b)/(c). |
| D5 | 2026-10-29 | Files behind a bot check are requested from the owner, never fetched by working around the check. | Respect the publishers' access controls. |
| D6 | 2026-10-29 | Plant-type codes: OSD, LIQ (oral liquids), SEMI (gels/semisolids), INJ (sterile injectables), API; ALL = every type. | Short tags for the catalogue and, later, the app filter. |
| D7 | 2026-10-29 | **Owner decision:** a regulator's own published English translation is allowed as a source (class `regulator_translation` in `sources/catalog.csv`). It goes through the same verification as official texts. The library and the app label these regulators "from the regulator's own English translation (not legally binding)". Third-party translations stay excluded. | Owner answer of 29 Oct 2026. Japan (PMDA) and Brazil (Anvisa) publish such translations. |
| D8 | 2026-10-29 | Japan and Brazil join Phase 2, because both map mostly onto the PIC/S core. The PMDA translation of Ordinance 179 (2021 amendment) is already stored. Anvisa's English RDC 658/2022 and RDC 654/2022 sit behind a Cloudflare captcha, so the owner downloads them. | Cheap to add after the pilot; access controls respected (D5). |
| D9 | 2026-10-29 | **Owner instruction:** for each pilot regulator, the library takes in every in-scope GMP guideline that body publishes (binding rules, final guidances, supplementary annexes, and the inspectors' own aides such as FDA inspection guides, compliance programs and PIC/S aide-memoires), not only the core GMP text. Priorities: `must` = binding text or what inspectors work from; `should` = final guidance that tightens a topic; `reference` = drafts and development-only guidelines (tracked, not turned into items until final). | Owner, 29 Oct 2026: "including all GMP guidelines as much as we can go for". |
| D10 | 2026-10-29 | **Owner decision (via lead session):** a plain-language question-answering assistant comes in a later phase. It is built on the verified library only, with no quotes or clause numbers for customers, every statement traced to verified requirements, and accuracy measured before release; internal version first. The owner is to get a lawyer's view on internal storage and processing of the WHO, PIC/S and ICH texts. Details in `docs/00-brief.md`. | Recorded for the plan (deliverable d); not built now. |
| D11 | 2026-10-29 | Owner uploads of 29 Oct are catalogued: EU Directive 2017/1572 and Regulation 1252/2014 (binding law), the two 2015 EU guidelines, Annex 19 old and new, the Glossary, the written-confirmation template, the EMA nitrosamines Q&A (Rev.23, Oct 2025), and Anvisa RDC 658/2022 (`regulator_translation`, phase 2). The revised Annex 19 (C(2026) 4135, 23 Jun 2026) is `must`; the 2005 version is kept as `reference` (superseded). Anvisa RDC 665/2022 and RDC 687/2022 are left out: they cover medical devices and in-vitro diagnostics (GMP and certification), not medicines. | Each file was checked against its first pages and its version. |
| D12 | 2026-10-29 | App stack: Python + Django + PostgreSQL, server-rendered with htmx (tablet browser). The library is stored as JSON/YAML in git, with a built SQLite for queries. Library model runs use the Anthropic Message Batches API: Opus 5.5 drafts and is verifier A; Sonnet 5.5 is verifier B. The customer export carries item text and tags only, and a test enforces option A. | Simple and one language, matching the pipeline. Details in `docs/02-plan.md`. |
| D13 | 2026-10-29 | **Owner decision:** a regulator × plant type may be released only if fewer than 0.5 % of its `must` requirements are unverified (was ≤ 5 %). Unverified items get up to two repair rounds (redraft, then full re-check); the pilot cost estimate rises to about US$950–1,650. | Owner, 29 Oct 2026. |
| D14 | 2026-10-29 | **Owner decision:** there is no Anthropic API key. All AI checking runs as Claude Code background agents on the owner's Max 20x plan: batches of about 40 clause units, structured JSON output, 2–3 agents at a time, resumable. Opus and Sonnet act as the two blind verifiers. A swappable model runner keeps the API or a RunPod GPU pod (a third, open-model verifier) possible later. RunPod CPU pods cannot run the checking at useful quality or speed. Pilot library time is now about 6–10 weeks. | Owner, 29 Oct 2026. Q1 resolved. |
| D15 | 2026-10-29 | **Owner decision:** Opus is used for both blind verifiers (and all other model roles). Independence comes from separately written prompts with different framing. Layer 3 measures whether that is enough. | Owner, 29 Oct 2026. Q2 resolved. |
| D16 | 2026-10-29 | **Owner decision:** no printing or export at all, including the site's own audit report and findings (Q4 = no). Consequence, recorded as a known gap: rule R6 (Annex 11 §8.1; 21 CFR 11.10(b), readable copies of records) is not met. It must be disclosed to customers; records are shown on screen. Option offered to the owner: an export of the site's own findings only, without our item text. | Owner, 29 Oct 2026. Q4 resolved. |
| D17 | 2026-10-29 | **Owner decision:** pilot on OSD + injectables; oral liquids, semisolids and APIs follow the pilot accuracy report. | Owner, 29 Oct 2026. Q5 resolved. |
| D18 | 2026-10-29 | **Owner decision:** release thresholds approved as in plan section 2.6 (with D13). Plan (b)-(d) approved; build starts with S1. | Owner, 29 Oct 2026. Q3 resolved. |
| D19 | 2026-10-29 | **Owner suggestion adopted:** classic NLP (no AI tokens, deterministic) is part of the pipeline: sentence splitting; detection of obligation words (shall/must/should/may) and numbers for Layer 1; TF-IDF/BM25 similarity to shortlist candidate clauses before any AI mapping call; and near-duplicate detection for shared texts (EU vs PIC/S) and for item wording that copies a source too closely. Built in S2/S3. | Fewer AI calls, more reproducible checks. |
| D20 | 2026-10-29 | Parsed clauses (`library/clauses/*.jsonl`, about 15 MB) are not committed: they are rebuilt from the fingerprinted sources by `tools/parse/run.py`. Only the parser code, its tests and `library/parse-report.md` are committed. | Derived data; avoids repo bloat and drift. |
| D21 | 2026-10-29 | **Owner-approved use of local models (transformers):** (1) **yes:** a small sentence-embedding model (e.g. bge-small or e5-small, CPU, version pinned and fingerprinted) alongside BM25 to shortlist candidate clauses for mapping (S2/S3); (2) **tables:** try pdfplumber (no AI) first on the table-format sources, and bring in a layout/table transformer (Docling or Table Transformer) only if misses remain; (3) **parked:** an NLI entailment model as an extra flag, revisited only if Layer 3 shows the two Opus verifiers share blind spots. Everything runs locally; no text leaves the environment. | Owner, 29 Oct 2026. Each model is kept only if it measurably helps. |
| D22 | 2026-10-29 | Tables are read with pdfplumber 0.11.10 (pinned in `requirements.txt`, installed in CI), for every non-FDA PDF: one clause per table row (`Table <k> <label>`, kind `table_row`), linked to the clause the table sits in (`parent`). The text around tables is still read with `pdftotext -layout`, band by band, so documents without tables parse exactly as before (tested). The cross-check accepts an obligation sentence on a table page when all its words are on that page, because raw mode reads tables across columns; it also drops running headers 10 lines deep. Docling / Table Transformer were not needed. | Table-format sources lost their sentence order in layout mode (211 possible misses). Deterministic, no AI. |
| D23 | 2026-10-29 | The WHO TRS side header ("WHO Technical Report Series, No. 1044, 2022"), which layout mode places mid-page, is removed from clause text when it recurs on at least 30 % of pages. Only that known pattern is removed: a general "repeated line" rule would also drop real list items (PIC/S PI 009). | Quotes must match the clause text word for word (Layer 1). |
| D24 | 2026-10-29 | FDA guidances and compliance programs are parsed by section (`tools/parse/headings.py`): the document's own table of contents is the outline, and a body line is a heading only when it matches the next contents entry (marker and first two words), so numbered lists in the body are never taken for headings. References follow the outline ("IV.B.2", "Part III 3.A"). fda.gov pages (`tools/parse/fdahtml.py`): Q&A pages give one clause per question ("Q7", with answer, references and date); other pages one clause per paragraph ("¶12") with the last heading as context, because some ORA guides place text before its heading in the HTML. The "large clause" flag for FDA sections is 15,000 characters instead of 4,000. | 60 pending FDA files; FDA texts are organised by headings, not numbered paragraphs. |
| D25 | 2026-10-29 | Three more parsers: EU legal acts (`articles.py`: "Recital (7)", "Article 5(2)", "Article 4(2)(a)"; Official Journal footnotes, numbered from (1) on each page, are kept out of the recitals); question-and-answer PDFs (`qa.py`: "Q7" = question with its answer, numbers in sequence, a contents list skipped); the EMA GMP/GDP Q&A web page (`emahtml.py`: "<topic> Q<n>", numbering restarts per topic). For non-FDA PDFs the numbered parser stays the default; `run.text_parser` switches to the Q&A or article parser only when it finds at least 3 clauses of its own kind and covers at least 5 points more of the text, and notes the switch on the first clause. | The EU legal acts, the EMA/PIC/S Q&As and the EMA web page parsed badly or not at all with the numbered parser. |
