| D24 | 2026-10-29 | FDA guidances and compliance programs are parsed by section (`tools/parse/headings.py`): the document's own table of contents is the outline, and a body line is a heading only when it matches the next contents entry (marker and first two words), so numbered lists in the body are never taken for headings. | D25 | 2026-10-29 | Three more parsers: EU legal acts (`articles.py`: "Recital (7)", "Article 5(2)", "Article 4(2)(a)"; Official Journal footnotes, numbered from (1) on each page, are kept out of the recitals); question-and-answer PDFs (`qa.py`: "Q7" = question with its answer, numbers in sequence, a contents list skipped); the EMA GMP/GDP Q&A web page (`emahtml.py`: "<topic> Q<n>", numbering restarts per topic). | D26 | 2026-10-29 | References are made unique without dropping text (`common.resolve_duplicates`): a repeated reference whose copy sits on a contents page, or is a short contents entry, becomes `toc`; numbering that genuinely starts again keeps its text and gets "#2", "#3" plus a note naming the heading it follows. eCFR: lettered sub-items below a roman numeral, italic numbers and romans below them (314.81(b)(2)(vii)(a)(8)(i)), and italic-term definitions (207.1 "Foreign"(2), 314.81(b)(3)(iii)(f) "Drug shortage") get their own references. | D28 | 2026-10-30 | Library format and Layer 1 (`tools/library/`). The library is plain JSON in git (`library/topics.json`, 19 topics with sub-topics; `library/requirements/<TOPIC>.json`; `library/coverage/<source>.json`), built into SQLite for the app (`build.py`, not committed). Layer 1 (`layer1.py`, no AI, exit 1 on any finding) checks for every mapping: the clause exists, its text hash matches (a changed text means re-verify), the quote is in it word for word (whitespace-normalised), the quote's wording gives the mapping's strength (shall/must = mandatory, should = recommended, may = optional) and the requirement takes the strictest mapping; plant types stay within the source's `applies_to` and every requirement plant type has a mapping; every number in the item text, addenda and parameters (string parameters too, and number words such as "twice") appears in a quote; numbers keep their sign and exponent (−20, 10³), word forms ("one"–"twelve", "once"/"twice") count only for whole numbers, decimal commas count, and a parameter may match a listed equivalent as whole words (12 months = "annually", not "semi-annually"). Strength is read from the main clause: "may not" is a prohibition (mandatory); conditions ("where … is required,"), relative clauses and the month May are ignored. A requirement marked `general` may take a mapping outside the source's plant types (plan 2.4 point 5). Coverage entries must name existing clauses and live requirements that really map them; coverage gaps are reported, not yet failed. Every source fingerprint is checked against `sources/inventory.csv`, and mappings to a changed source are flagged for re-verification. Clauses come from `library/clauses` or, when absent (CI, D20), are parsed on demand. | Plan section 2.4. Rules are deliberately strict; anything Layer 1 cannot settle goes to the verifiers. |

| D30 | 2026-10-30 | **Owner decision (revises D29):** no API credits are used. Drafting and verification run as Claude Code agents in sessions on the Max plan, with one model for every role (D15), as first planned in D14. | D31 | 2026-10-30 | **Owner decision:** both verifier prompts are tightened after the pilot-scale mutation test (PR #22): a verifier judges only what the item's own words say and must not read the clause back into it. A condition, trigger ("if", "where ... is required", "when") or timing ("before", "at completion of") that is in the clause but not in the item is an omission, even if it seems implied. Each prompt states this in its own framing (A item-first, B clause-first) so the two stay independently worded (D15). `tests/test_ai_sessions.py` pins the rule. Earlier run folders keep the prompts they were run with. | Owner, 30 Oct 2026: both misses across the two mutation runs (WHO 8.9 "before approval", Schedule M 10.8.2 "where an audit is required") came from a verifier filling a dropped condition back in from the clause. |
| D32 | 2026-10-30 | Candidate search (D21) is `tools/search/`: BM25 over clause words (`bm25.py`, pure Python, light stemming) and the pinned embedding model bge-small-en-v1.5 (MIT; revision `5c38ec7`, every file sha256-pinned in `embed.py`, run as ONNX on CPU, fetched into `models/`, not in git), fused by reciprocal rank (`candidates.py`). Candidate search only proposes clauses; every pairing is still drafted and verified. | D21: a model is kept only if it measurably helps.
